# Agent Lessons Learned (Self-Improvement Loop)

> **Every new agent MUST read this file before starting work** so the next run never repeats a mistake.

## How This Self-Improvement Loop Works
1. **Before you start:** Read every active rule below along with `GAME_DESIGN.md` and `DEVLOG.md`.
2. **Every run (or every few runs):** Review the saved logs of recent runs — `DEVLOG.md`, your agent's saved run logs/transcripts when accessible (e.g., Antigravity's `.system_generated/logs/transcript.jsonl`, Claude's session logs), and any corrections the team gave you during the session.
3. **Record new lessons:** For every failure, preventable tool error, wasted-token/time detour, or user correction, add a short rule in the format **`Rule`** — *Reason*.
4. **Fix wrong or outdated rules:** If a rule turns out to be wrong, overly broad, or fixed in the codebase, **update or delete it** immediately. Keep entries concise and deduplicated.

## Roblox Studio & MCP
- **Check Studio mode (`get_studio_state`) before running `execute_luau`:** `Edit` datamodel fails in Play mode, and `Server`/`Client` datamodels fail in Edit mode. — *Reason:* Calling the wrong datamodel wasted 4 consecutive MCP error round-trips during Play-mode testing.
- **Always put explicit timeouts on yields inside `execute_luau` (especially on `Client`), and don't queue slow calls in parallel with `get_console_output`:** Never write unbounded `WaitForChild()` or `CharacterAdded:Wait()` in test scripts. — *Reason:* An unbounded client yield stalled the Roblox Studio MCP queue for 3 full minutes (`context deadline exceeded`) twice in one session, blocking parallel `get_console_output` calls behind it.
- **Inspect remotes in Edit mode before flagging unknown Play-mode remotes:** `ServerScriptService.AntiCheat` intentionally renames `ReplicatedStorage.Remotes.DevRemote` to a random string at runtime (e.g., `VYUCVTYJIDVADSUTPCV`). — *Reason:* Avoids wasting turns investigating or breaking the anti-cheat remote.
- **Avoid calling `WaitForChild` on `StarterGui.Cmdr` children without a replication guard:** Wait for `StarterGui.Cmdr` / `PlayerGui` replication safely inside `CmdrController`. — *Reason:* Unchecked `CmdrClient` initialization yielded indefinitely on `Window` and broke client test execution.
- **First-person vehicle limb visibility requires resetting `LocalTransparencyModifier = 0` on `RenderStepped`:** Roblox's default `CameraModule` forces `LocalTransparencyModifier = 1` on all character parts in first person (`LockFirstPerson`). — *Reason:* Seated drivers and passengers couldn't see their own hands on the steering wheel or feet on the pedals even though limbs were positioned correctly.
- **R6 Motor6D aim channels must include fallback tip vectors:** Always provide default limb tip offsets (`(0, -1.5, 0)` for arms, `(0, -2, 0)` for legs) instead of failing when attachments like `LeftGripAttachment` or `RightFootAttachment` are absent. — *Reason:* Standard R6 avatars lack `LeftGripAttachment` by default, causing whole-rig initialization to silently abort.
- **Disambiguate duplicate seat names in vehicle models:** Differentiate front cab shotgun seat as `FrontPassengerSeat` or verify relative coordinates (`rel.Z < -5 and rel.X > 0`). — *Reason:* `model.Seats.PassengerSeat` returned a rear cargo bench seat 16 studs away instead of the cab passenger seat, breaking door prompts and shotgun seating.
- **Vehicle cab seating posture (head forward, torso back against backrest):** Setting `SeatWeld` forward shoves the entire torso directly under the first-person camera. Instead, seat the torso back against the backrest (`CAB_SEAT_SHIFT <= 0.2`) and lean the `Neck` joint forward (~`0.45` studs in torso space) when seated, with `UpperTorso` hidden in R15. — *Reason:* Naturally positions the eyes ahead of the chest so looking down reveals the lower abdomen and pedals without chest occlusion.
- **Exiting enclosed vehicle seats with Roblox `AvatarAbilities` / `ControllerManager`:** `CharacterContext.JumpAction` intercepts `Space` before `InputBegan` and skips `Humanoid.Jump`, and an enclosed cab roof lets `Seat` touch-to-sit immediately re-seat the player. Edge-detect `Space`/`ButtonA` in the seated `RenderStepped` loop (plus `JumpRequest`), fire a server `LeaveSeat` action, temporarily set `seat.Disabled = true`, destroy `SeatWeld`, set `hum.Sit = false`, wait until `hum.SeatPart == nil`, and `char:PivotTo` beside the open door. — *Reason:* Players were permanently trapped in van seats with `ControllerManager.ActiveController = nil` and could not exit or move.
- **Wait for `DeliveryVan.VanControl` before binding `VanAnimController` and never drop the final `"Pose"` packet:** Require `VanControl` in `tryBind()` (with lazy re-lookup) and queue rate-limited pose updates in `VanDrive` to flush on `Heartbeat`. — *Reason:* `VanAnimController` previously bound as soon as `SteerJoint` replicated—before `VanControl` existed—permanently caching `refs.control = nil` so zero pose updates reached other players.
- **Use server-authored `ClosedC0` / target `Attachment`s and idempotent `Motor6D.C0` solving for R6 remote animations:** Store `ClosedC0` and create `VanAnim*` attachments once on the Server, and solve R6 limbs by setting `motor.C0` relative to saved `defaultC0` (canceling `motor.Transform`) rather than mutating `motor.Transform` twice per frame. — *Reason:* Eliminates `StreamingEnabled`/late-join misalignment, double-lerp drift, and frozen limbs on throttled remote players.
- **Never render window-facing monsters or VFX behind `Enum.Material.Glass` using `SurfaceGui` or semi-transparent parts:** Roblox's `Glass` material occludes `SurfaceGui`s and `Transparency > 0` parts behind it. Build window monsters with opaque (`Transparency = 0`) 3D geometry (including opaque `Neon` eyes) positioned cleanly outside the glass (`BulkMoveTo` on anchored non-colliding client parts). — *Reason:* The previous 2D `WindowMonsterSilhouette` (`Transparency = 1` + `SurfaceGui`) was invisible through `SideGlassL/R` (`Material = Glass`), making players think no window monster existed.
- **Never `require(ReplicatedStorage.CmdrClient)` inside `execute_luau` on `Client`:** Calling `require` inside `execute_luau` runs `CmdrClient` initialization in an isolated VM and hangs. Invoke `ReplicatedStorage.CmdrClient.CmdrFunction:InvokeServer(...)` directly instead. — *Reason:* Calling `require(CmdrClient)` hit the 3-minute MCP timeout during Play-mode Cmdr verification.
- **Keep `SurfaceGui` glass/crack overlays at `LightInfluence >= 0.5` with muted frost & dark fracture tones:** Pure white frames at `LightInfluence = 0.25` trigger `Bloom` glare in Lighting and wash out anything viewed behind the glass. — *Reason:* Stage 3–4 window spiderweb cracks stayed razor-sharp while keeping the monster's glowing eyes clearly visible once changed to `LightInfluence = 0.55` and `Color3.fromRGB(205, 225, 238)`.
- **Strip post-camera shake `CFrame` offsets at `Enum.RenderPriority.Camera.Value - 5` before Roblox `CameraModule` (`200`) runs:** Applying camera shake at `Camera.Value + 25` without un-applying it (`cam.CFrame * lastAppliedShakeCF:Inverse()`) before `CameraModule` samples `cam.CFrame` causes cumulative camera aim drift while players freely look around. — *Reason:* Adding `WindowMonsterCamPre` at priority `195` kept camera rotation rock-steady once initial forced-look released at `0.95s` (`FreeLookAwayFwdDot = 0.950`).
- **Keep `StarterPlayer.LuaCharacterController = Enum.CharacterControlMode.Legacy` and actively strip Studio `AvatarAbilities` / `ControlState` beta injections (`LegacyCharacterFix`):** Even with `LuaCharacterController = Legacy`, Studio's experimental `AvatarAbilities` / CCL beta still injects `AbilityManagerActor`, `ControllerManager`, `ControlState`, and sets `Humanoid.EvaluateStateMachine = false`, which makes `PlayerModule`'s `AvatarAbilitiesInterface:isEnabled()` ignore `JumpAction` in favor of disabled `AbilityAction1` (breaking jumping) and freeze movement on Team Test when `ControlState` mismatches the cloud server. Stripping those beta instances on Server, restoring `HRP.CollisionGroup = "Default"`, and enforcing `EvaluateStateMachine = true` restores classic `ControlModule` movement/jumping cleanly without errors. — *Reason:* Diagnosed `dY=0.00` jump failures (`JumpAction=true, AbilityAction1.Enabled=false`) and Team Test lockouts; verified `dY=7.31`, `dXZ=8.22` after cleanup.
- **Resolve `StarterPlayerScripts` child references via `script.Parent` (`ClientBootstrap`):** Never traverse `StarterPlayer:WaitForChild("StarterPlayerScripts")` from a running client script; `StarterPlayerScripts` contents clone into `LocalPlayer.PlayerScripts` on join/Team Test. — *Reason:* Avoids infinite yield / missed controller bootstrap on live servers and Team Test clients.
- **Anchor window-facing monsters to `WindowJoint<side>.Part0.CFrame * ClosedC0` instead of `SideGlass.CFrame`, and bound `"Attack"` door-blocks by `WindowThreatEventTime`:** Once `SideGlassL/R` rolls down via `WindowJointL/R` (`relY = 5.85 -> 2.80`), anchoring to live `glass.CFrame` drops the monster inside the door panel; likewise `WindowMonster._fail()` leaves `WindowThreatEvent = "Attack"` set until the next threat/reset (`Reset()`), so door blocking must expire after the `3.0s` breach window and listen to `WindowThreatEventSeq`. — *Reason:* Kept `WindowMonster3D_L` at `MonsterHeadRelY=5.76` with window rolled down and prevented permanently jammed doors after attacks.
- **Avoid deprecated `rbxasset://sounds/swoosh.wav` for runtime fallback `Sound`s:** Roblox logs `Failed to load sound rbxasset://sounds/swoosh.wav: Asset is not approved for the requester` in Studio; use verified built-ins like `rbxasset://sounds/action_falling.mp3` or `action_footsteps_plastic.mp3` / `action_jump_land.mp3`. — *Reason:* Caught and eliminated `WindowMotorSfx` load errors during the `LogService` audit.
- **For seamless in-vehicle seat switching without standing up (`Seat:Sit` requires `hum.Sit == false` + `~0.18s` post-unsit cooldown, and R6 bent legs alter `SeatWeld.C1`):** Roblox's `Seat:Sit(hum)` returns early and does nothing if `hum.Sit == true`, AND when an R6 avatar's legs are already bent forward in a seated pose, `Seat:Sit(hum)` computes `SeatWeld.C1.Y = -0.76` from the bent-leg extents instead of canonical `-1.50` (dropping the avatar and camera by `0.74` studs, while `VehicleSeat` also hijacks `CameraSubject`). Transfer `SeatWeld` to `SwitchSlideWeld` and set `hum.Sit = false` at `t = 0`, explicitly restore BOTH `newSw.C0` AND `newSw.C1 = CFrame.new(0, -1.5, 0) * CFrame.Angles(-math.pi/2, 0, 0)` after `target:Sit(hum)`, and keep `Camera.CameraSubject = hum` in first-person cab view. — *Reason:* Fixed `target:Sit(hum)` no-oping when `hum.Sit == true` and eliminated the `0.74`-stud driver camera drop (`camY: 5.41 -> 4.68` fixed to `5.41 -> 5.42`) when switching from `FrontPassengerSeat` to `DriverSeat`.

- **Build procedural IK limbs with their rest geometry aligned along a single axis (arms along -Z, trailing legs along +Z) and identity-rotation pivots:** Then world bone CFrames are just `CFrame.lookAt(joint, nextJoint)` (times `Angles(0, math.pi, 0)` for +Z limbs), with no rest-rotation correction math. — *Reason:* The Colossal Skinwalker's 2-bone arm IK and Verlet ragdoll legs worked on the first Play test with hands landing exactly on the van sides (`±5.0` studs).
- **Studio `screen_capture` during Play mode can return only the UI layer:** Verify 3D client visuals with numeric checks (attributes, extents, bone-to-target distances) or ask the user to look in-game. — *Reason:* A capture of the Colossal Skinwalker showed only HUD/notifications over a blank background.
- **A forced Cmdr chase keeps running on its own between `execute_luau` calls:** Sample state in the same call right after spawning (or spawn far away). — *Reason:* A parked van let the chaser grab twice and evade in about 6s, so the next call found it already gone.
- **Never disable touch-to-sit by toggling `Seat.Disabled = true` when empty and flipping `Disabled = false` on the same frame as `Seat:Sit(hum)` (and set `ModelStreamingMode = Persistent` on vehicles when `StreamingEnabled = true`):** Keep `Seat.Disabled = false` permanently and block accidental walk-over sitting with `CanTouch = false`, `CanCollide = false`, a non-collidable `CollisionGroup`, and stripping any `TouchTransmitter`. — *Reason:* Same-frame `Disabled` toggling races with Roblox replication/ownership (`DriverSeat`), breaking `SeatWeld` and kicking seated players out.

- **Roblox `VehicleCamera` snaps the view to yaw `0` / pitch `-18` whenever the avatar becomes seated in a `VehicleSeat` (`DriverSeat`), but not in a plain `Seat`:** Capture the look direction in chassis space while the `[C]` slide runs and re-apply it with a render step at `Camera.Value + 1` for ~`0.4s` after landing. — *Reason:* Passenger -> driver switches snapped the view forward; measured fix kept yaw within ~0.5 degrees. (`cam.CFrame` set from script is honored by `VehicleCamera`, so a short override is enough.)
- **Measure van motion before guessing at seat-switch physics bugs:** Sample `DeliveryVan.PrimaryPart` Y/`AssemblyLinearVelocity` on the Server every `Heartbeat` while firing `SwitchSeat` from the Client, after the van has settled. Disabling character collisions and mass (`VanSeat` group + `Massless`) did NOT remove the ~1.4 stud van jump on `[C]`, so don't repeat that. — *Reason:* Avoids another round of unproven fixes; see the DEVLOG entry for the remaining suspects.
- **Studio Play sessions can end by themselves and the MCP connection can drop (`No Roblox Studio instances are connected`):** Check `get_studio_state` before every edit (`multi_edit` only works in Edit mode) and keep experiments short. — *Reason:* Studio flipped between Edit/Play mid-session and finally disconnected during the van-jump investigation.

- **`require(Loader)` inside `execute_luau` gives an isolated copy, so `Loader.Get("SomeService")` fails with "Module ... is not registered" even when the live service is running:** Verify services through remotes, `leaderstats`, attributes, or the Cmdr `CmdrFunction:InvokeServer("setcash 1000")` instead.  *Reason:* Wasted two Server calls concluding a service had failed to boot while it was healthy.

## Game Architecture & Live Place Gotchas
- **Check existing frameworks (`Loader`, `Cmdr`, `ProfileStore`, `AntiCheat`) before designing a feature:** Build admin commands inside `Cmdr`, and build game systems as `Loader`-managed Services/Controllers (`Loader.Get(...)`) instead of standalone `Script`/`LocalScript` instances. — *Reason:* The user had to clarify using `Cmdr` for admin commands and later asked to refactor standalone van/shop/chute scripts into modular Services and Controllers.
- **Exempt new movement/vehicle mechanics in `AntiExploitService`:** Any boost, high-speed driving (van boost `140` > `120` cap), server-set `WalkSpeed`, or admin flight (`AdminFly`) must be explicitly exempted. — *Reason:* Otherwise `AntiExploitService` falsely flags or rubber-bands legitimate gameplay and admin testing.
- **Account for `HorrorKit_Houses` porch collision bounds:** `HorrorKit_Houses` meshes (`Default` CollisionFidelity) block players ~`4.2` studs in front of porches. — *Reason:* Delivery `ProximityPrompt`s need generous range (`MaxActivationDistance >= 14`, `RequiresLineOfSight = false`) so front-of-porch drop-offs work reliably.

## Blender MCP & 3D Asset Pipeline
- **Pass individual field names to `Blender.get_scene_info`:** Use `location`, `size`, `ground`, `details`, `weights`, `topology`, `settings` — never category headings like `placement` or `contents`. — *Reason:* Passing category headings fails with `Error: unknown fields`.
- **Bypass `Blender.get_addon_status` if it raises `No module named 'blender_mcp.config'`:** Query Blender version and scene state directly via `execute_blender_code`. — *Reason:* Addon version mismatch causes `get_addon_status` to fail even while all modeling/export tools work normally.
- **Solo the target collection before calling `look` when multiple assets share `(0, 0, 0)`, and purge orphan datablocks before exporting:** Run `bpy.ops.outliner.orphans_purge(...)` after rebuilding a mesh or armature. — *Reason:* Prevents overlapping renders at origin and keeps `.001` suffixes out of exported rig/mesh datablock names.
- **Never call `bpy.ops.wm.read_factory_settings(...)` through Blender MCP:** Resetting factory settings unloads the live `blender_mcp` addon and severs the MCP socket. — *Reason:* Forced a Blender restart when starting a fresh scene for `roads.blend`; remove unneeded objects/collections directly in Python instead.
- **Bake multi-material Blender props onto a single UV palette atlas texture (`512×512`, subtle grain per swatch) before exporting `.glb` to Roblox:** Exporting one material + embedded atlas image keeps every prop as a single clean `MeshPart` with all colors preserved via `TextureID` (and avoids flat-color moderation rejections). — *Reason:* All 8 multi-color road formations imported into Studio on the first try sharing one `TextureID` (`rbxassetid://116369928377682`) with zero dropped colors.
- **In a group-owned place where a teammate lacks group asset-create permission, use Studio's built-in File → Import (`Ctrl+M`) with Creator switched to their personal account:** Open Cloud `POST /assets/v1/assets` rejects `groupId` (`unauthorized`) and rejects `userId` (`User not authenticated`) because the Studio MCP token is bound to the group place. — *Reason:* Avoided repeated 403 upload loops when importing the 6 dead tree `.glb` meshes.
- **Always restore `part.Size` from `templateBaseSize[assetName]` when acquiring scaled meshes from `ChunkBuilder`'s pool:** Record original template sizes during `ensureInit()` and explicitly set `p.Size`, `p.CanCollide`, and `p.CanQuery` on every pool pop. — *Reason:* Prevents pooled trees with distance-based scaling and roadside vs. deep-forest collision rules from leaking stale scale or collision flags across chunks.

## Git, Docs & Team Workflow
- **Never run a bare `git push` that can hang waiting on interactive HTTPS prompts:** Run `GIT_TERMINAL_PROMPT=0 git push` so it fails fast when credentials aren't cached, then give the user the commit hash to push via GitHub Desktop. — *Reason:* Non-interactive terminals without macOS Keychain GitHub tokens hang or fail on username prompts.
- **On Windows without `git` on `PATH`, use GitHub Desktop's bundled `git.exe`:** Located at `%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe` (version folder updates automatically with GitHub Desktop). — *Reason:* Saved teammates using Claude on Windows from failing git sync steps.
- **Use exact repo filenames (`GAME_DESIGN.md`, `DEVLOG.md`, `LESSONS.md`):** Verify filenames before referencing them. — *Reason:* `GAME DESIGN.md` previously had a space mismatch against the instruction docs and caused lookup confusion.
- **Keep shared AI instructions (`GEMINI.md`) team-neutral regarding developer names:** Other teammates also use Antigravity on their own machines/accounts; instructions should prompt for each developer's name rather than hardcoding a single developer for the whole repo. — *Reason:* Avoided mistakenly attributing teammates' future Antigravity changes under the wrong user.

- **When new decoration/detail folders are added to the van, check `VanDrive`'s `owner` table covers them:** Anything not in `owner` is welded to the chassis and stays put when a door moves (`RearDoors.LeafDetailL/R` were missed that way). Check with a Server Play test: rotate the door `Weld` and measure each detail part's drift relative to the door root. — *Reason:* 96 rear door detail parts stayed behind when the rear doors opened.
- **Never put `]]` inside a Luau `[[ long string ]]` in `execute_luau` (e.g. `rd["RearHandle"..side]]`):** Use `[=[ ... ]=]` when patching script source from code. — *Reason:* A `[[ ]]` patch containing `side]]` failed with `Failed to parse command code`.
- **To Play-test a server-local handler in `execute_luau`, add a temporary RemoteEvent that calls it, then delete it:** `ProximityPrompt:InputHoldBegin()/InputHoldEnd()` called from the test VM does not fire the connected `Triggered` handler, and local functions in a running `Script` cannot be called externally. — *Reason:* Three prompt-hold attempts from both Server and Client VMs left the seat unchanged; a short-lived `TempTestEnterSeat` remote verified the animated enter/exit path in one pass, then was removed.
- **Apply character herding knockback on the client via a replicated `Vector3` attribute (alongside `AntiExploitService:ExemptMovement` and `hum:ChangeState(Freefall)`):** Writing `hrp.AssemblyLinearVelocity` solely from the Server on a client-network-owned character yielded `vel = 0.0` on the client; replicating `ForestHunterKnockback` and applying it in `ForestHunterController` immediately produced `peakVel = 73.0` (`13.6` studs displacement in `0.35s`). — *Reason:* Caught during `forestmonster attack` Play-mode verification before finishing.
- **When a player transitions into/out of a vehicle, keep character parts `Massless` until they are actually clear of the vehicle — not just for a fixed `0.2s`:** Restore the normal collision group right after the welded slide, but leave `Massless = true` and poll until the HRP exits a chassis-local keep-out box. — *Reason:* Rear van seats put the player `~1.9` studs from the seat, still inside the cargo body; restoring collisions after 0.2s let walking/standing up depenetrate against the cab and spin or flip the physics-owned van.
- **Vision-only head/neck offsets must be applied to the local avatar alone:** Gate `HEAD_FORWARD_OFFSET` (and similar first-person camera offsets) with `char == localPlayer.Character` so remote avatars keep their default bone positions. — *Reason:* Applying the seated forward neck shift to every avatar made other players look hunchbacked; the local camera still needs the offset to see clearly.
- **Keep character-to-vehicle slide welds pure translation; never bake lift/pitch/roll into the physical `C0`:** Draw the arc cosmetically on the client from the `VanSwitch*` attributes instead. — *Reason:* The van's `SwitchSlideWeld`/`VanEnterWeld`/`VanExitWeld` lift and tilt terms were transmitted into the physics-owned chassis, raising it ~1.3 studs and peaking at `1.323 rad/s`; translation-only slides dropped the peak to `<= 0.015 rad/s` with zero Y drift.
- **Keep preloaded `Sound` instances pooled under `SoundService` (or an `Attachment`) and run `ContentProvider:PreloadAsync` inside `task.spawn`, never synchronously inside `Start()` or `execute_luau`:** Creating temporary `Parent = nil` sounds to preload and destroying them left `APMOfficial` one-shot stingers unloaded on short checks, and synchronous `PreloadAsync` / `Loader.WaitReady()` inside `execute_luau` can stall until MCP timeout when another controller lags on boot. — *Reason:* Switching to pooled `Sound` children under `SoundService.GameMusicAudio` verified `18/18` official audio assets (`10/10` music/stingers + `8/8` van sounds) loaded with zero errors.
- **Verify the active workspace points to `GitHub\Horrorr-Game` before starting or ending a session:** Check `.git` presence instead of assuming another folder (e.g., `Documents\P.A.R.A.L.L.A.X`) is tracked, and check `View → Drafts` in Studio Team Create. — *Reason:* Working out of an untracked starter folder left a full day's Studio milestones unpushed to GitHub while 20 teammate commits landed on `origin/main`.
- **Never use parenthesized tuple returns inside Luau `if ... then ... else (0, 0, 0)` expressions:** Expand multi-value returns into standard `if ... then ... else ... end` statements instead of inline expressions. — *Reason:* A ternary `else (0, 0, 0)` in `TaxService:235` failed Luau compilation during cross-place settlement setup.
- **Match unanchored cargo `BasePart` network ownership to the `DriverSeat` occupant and enforce door-aware `Heartbeat` containment:** Sync `InVan` box ownership dynamically with the active driver (resetting to auto when dropped) and clamp against closed walls/doors (client when driving, server when parked) while leaving open doors unobstructed. — *Reason:* Server-owned cargo fighting a client-owned driving van caused severe physics jitter and high-speed wall tunneling until ownership and containment matched in lockstep.
- **Clean up vehicle enter/exit/seat welds and attributes on `Humanoid.Died`/`CharacterRemoving` and guard client listeners with `charConns`:** Clear transition/seat welds, restore seat/collision flags in `VanDrive.cleanupPlayerVanState`, and disconnect per-character connections in `VanController` on character removal/death. — *Reason:* Dying mid-entry or while seated left avatars stuck in floating crouch poses, broke van seat controls on subsequent entry, and allowed stale `VanSwitchActive` callbacks to break first-person camera locking.
- **Store `accountProfiles[userId]` in `DataService` and call `FlushPlayer` (`accProf:Save()`) before cross-place `TeleportService` calls:** Track loaded account profiles explicitly and force-flush `ProfileStore` writes immediately before `TeleportAsync` / `TeleportToPrivateServer`. — *Reason:* Missing `accountProfiles[userId]` persistence and unflushed teleports can drop or session-lock cross-place `LobbyCurrency` (`Credits`) and `LastSettlement` data between places in the same Universe.
